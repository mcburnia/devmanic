# Microapp Opportunity Research

## Core finding

The useful market gap is rarely “no app exists”. It is:

> People cannot find a small, trustworthy, no-account tool that performs one precise job without subscriptions, bloat or opaque data use.

This supports a Devmanic promise:

> **Small, useful apps that do one thing properly. No unnecessary account. No unnecessary subscription. No nonsense.**

## Demand themes

Research and current user discussions repeatedly indicate:

- subscription fatigue for tiny utilities;
- task/productivity products becoming more complex than the problem;
- demand for local/private file processing;
- precise calculators that model real-life exceptions;
- tools that record completed work rather than increasing the outstanding workload;
- long-term goal tracking absent from weekly time trackers;
- human-readable infrastructure and security explanations.

## High-opportunity general tools

### Shift Pay Calculator

Model multiple rate bands in one shift, unpaid breaks, overtime and weekend/holiday enhancements.

### Hours-to-Goal Tracker

Timer plus cumulative lifetime target, progress and completion projection.

### Done List

Record completed work, produce summaries and support appraisal/status evidence.

### Subscription Reality Calculator

Expose cumulative cost, introductory pricing and expected increases.

### Deadline Chain Calculator

Work backwards from a deadline through working days, dependencies and contingency.

### Image Metadata Inspector & Cleaner

Inspect and remove location/device information locally.

### Human Cloud Cost Calculator

Translate users, visits, storage and data transfer into understandable infrastructure estimates. Retained as a later opportunity because prices require maintenance.

### Recipe/Pan Rescaler

Combine servings, pan area/depth, metric/imperial and baker's percentages.

### Will It Fit? Calculator

Check whether rectangular furniture/appliances fit through doors and constrained spaces, with transparent assumptions.

## Portfolio balance

Devmanic should combine:

- broad/shareable tools for reach;
- tracked/hosted tools for return visits;
- developer tools for relevant authority;
- security/SBOM tools for a natural CRANIS2 relationship.

## SEO principles

- one permanent route per useful tool;
- indexable explanation, worked examples and FAQs;
- avoid thin near-duplicate pages;
- use structured data where appropriate;
- earn independent links through utility;
- do not attempt to pass authority through arbitrary user-generated links;
- mark user-generated or affiliate links appropriately;
- distinguish static from tracked URLs and QR codes transparently.

## Promotion principles

CRANIS2 exposure should be restrained:

1. universal: subtle “supported by CRANIS2” attribution;
2. contextual: a relevant explanation where the tool relates to lifecycle security/compliance;
3. user-initiated: a page explaining why CRANIS2 supports free developer tools.

A Devmanic tool must remain worthwhile if the user ignores CRANIS2 completely.
